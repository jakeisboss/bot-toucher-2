# BT2 0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build only the approved Windows-first BT2 0.0 shell.

**Architecture:** WPF owns presentation; a small portable core owns validated shell layout/preferences and the application-lifetime sampling loop. Windows telemetry is an isolated service with no workload dependencies.

**Tech Stack:** .NET 8, WPF, xUnit, Windows performance counters.

**Spec:** `docs/superpowers/specs/2026-11-10-bt2-0.0-design.md`

## Global Constraints

- Version 0.0.0, independent BT2 project, existing isolated checkout on branch `work`.
- Central content boundary only; no widget host/runtime, packet runtime, updater, allocator, executor, results or workload logic.
- Monitor starts with application, cancels on close, awaits in-flight sampling before disposal.
- Invalid preferences: safe defaults, visible notice, no silent overwrite.
- Windows launch/interactions remain unverified until executed on Windows.

## Review Focus

- Corrupt/null/unsupported preference JSON and external file replacement must not be silently overwritten.
- Invalid layout widths and unknown navigation IDs must fall back safely.
- Closing during sampling must wait before disposing resources.
- Telemetry errors must not kill the shell or create overlapping polls.
- Hidden rails must remain restorable and minimum window size must preserve workspace access.
