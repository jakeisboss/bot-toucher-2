# BT2 0.1 implementation plan

> Use subagent-driven-development for the isolated updater library task, then integrate the tightly coupled application/CLI frontend and perform an independent whole-branch review.

Goal: corrected 0.1 shell/UI refinements and one manual transactional updater, only.
Spec: `docs/0.1/DESIGN.md`; authoritative checklist: `docs/0.1/DEFINITION-OF-DONE.md`.

## Global constraints

No widget host/runtime/contracts, DLL loading, messaging/actions, lifecycle/crash/proof/persistence implementation. No packets, workloads, allocator, CPU/GPU execution or results architecture. No automatic startup checks/downloads/installs/tests/benchmarks. One updater engine; manual GitHub Releases, one channel; compiled assets never committed to Git. Windows execution remains unverified until actually run there. Existing shell preferences and hardware lifetime remain safe.

## Review focus

- Interrupted pending activation versus committed current.json must preserve previous known-good rollback and exact state bytes.
- Source/payload/stage corruption, path aliases and reparse points fail before live activation.
- Status/check must not touch payload data or hash/scan installations.
- Candidate readiness failure must restore previous active identity without rotating rollback.
- Shell theme/rail migration, Home real information/activity and startup must introduce no future runtime.

## Task 1: Shared update library and portable transaction tests

Files: new `src/BotToucher2.Update/*`, `tests/BotToucher2.Update.Tests/*` only.
Interfaces: inventory/transition planner, streaming asset source, one UpdateEngine with status/stage/apply/rollback/recover, launch/readiness boundary and GitHub metadata client. Engine contains no WPF dependency; launch is an injectable OS boundary.

- [ ] Inspect corresponding BT1 later updater validation and owned-path checks.
- [ ] Publish precise public API in a contract note before integration work.
- [ ] Write tests first: source mismatch; add/replace/delete/unchanged; download counts; hash failure; staged target tamper; apply/readiness success/failure; interrupted recovery; rollback/reapply/rotation; 1.0 anchor; status/check metadata-only; path/reparse validation.
- [ ] Implement portable shared engine, receipts/journal, exact source/target verification, bounded public-GitHub metadata transport and asset streaming. No parallel repair authority.
- [ ] Run targeted tests, self-review and commit owned files. Independent source review before acceptance.
